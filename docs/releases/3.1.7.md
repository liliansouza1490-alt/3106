# 3.1.7 正式版

发布日期：2026-11-10

3106 3.1.7 修复壁纸安装链路、改善清理器加载体验，并修复“收藏文件夹打开后列表为空”的问题。

## 壁纸：参考实现与本次修复

参考项目 **Erosion** 的做法：

1. 解包 `.tendies`，按目录名/内容区分 `com.apple.WallpaperKit.CollectionsPoster`、`com.apple.MercuryPoster`、`com.apple.PhotosUIPrivate.PhotosPosterProvider`。
2. 对每个 descriptor 重写三处 ID：
   - `com.apple.posterkit.provider.descriptor.identifier`
   - `com.apple.posterkit.provider.contents.userInfo` 的 `wallpaperRepresentingIdentifier`
   - `Wallpaper.plist` 的 `identifier`
3. 非 Mercury 使用随机 UUID 目录名，Mercury 保留原目录名。
4. 复制到 PosterBoard 容器的 `Library/Application Support/PRBPosterExtensionDataStore/61/Extensions/<provider>/descriptors`，然后打开 PosterBoard 刷新。
5. 超过 5 个 descriptor 会提示，最多 15 个左右。

3106 本次修复：

| 问题 | 修复 |
| --- | --- |
| PosterBoard 存储没有数字 generation 目录时，扫描先 `throw`，导致 27.3 的递归/`61` 兜底永远不可达 | 移除提前抛错，先尝试递归布局，再回退到 `61` 兼容布局 |
| 多个 generation 时总取最高数字，可能装到 PosterBoard 不读取的旧 generation | 优先选择已经包含包所需 provider 的 generation |
| Mercury 壁纸目录名被随机 UUID 覆盖 | Mercury 保留原 descriptor 目录名；其他 provider 仍用 UUID |
| 视频 descriptor（含 `VideoCAML`）被装进 Collections | 识别 `VideoCAML` 后安装到 Photos provider |
| descriptor 文件直接放在 `descriptors/` 下时解析为空 | 将整个 `descriptors/` 作为一个 descriptor 处理 |
| 失败后难以定位 | 增加 layout generation、extensions、每个 descriptor 目标路径的诊断日志 |

## 清理器：增量加载

- 改为**每处理完一个应用就刷新列表**，不再等整批测量完成。
- 列表底部新增加载行：`已加载 N 个应用 · M 个有可清理数据…`，随扫描实时增长。
- 扫描期间即使还没有任何可清理数据，也会显示加载行，而不是“空列表”。

## 收藏夹：打开后列表为空

- 新标签页直接打开收藏的子目录时，视图不是 root，旧逻辑会跳过 sandbox grant，导致目录能进入但文件列表为空。
- 现在首次加载始终对**容器根**（`containerPath`）申请授权，再列出收藏目录；收藏的文件夹可直接显示内容，无需再点进去。

## 验证方法

1. 壁纸：导入 `.tendies` → 确认报告显示可安装 → 安装后按提示关闭 PosterBoard，再查看锁屏壁纸选择器。
2. 日志应出现 `wallpaper: layout generation=... extensions=...` 和 `wallpaper: install <provider> <name> -> <path>`。
3. 清理器：进入清理页，底部计数应持续增长，列表逐条出现；扫描完成后加载行消失。
4. 收藏：在文件标签页点击收藏的文件夹，应直接看到该目录内的文件；若为空，日志应显示 `filebrowser: traversal grant container=...`。

## 已知限制

- PosterBoard 的壁纸列表刷新仍依赖系统进程；安装后请按提示关闭 PosterBoard 或重新打开锁屏壁纸选择器。
- iOS 27.3 beta 的 PosterBoard 布局可能继续变化；诊断日志会输出实际 generation 与 provider 列表。
- 壁纸数量建议不超过 15 个 descriptor。
