# 3106 3.1.11 测试版（未发布）

发布日期：2026-11-10

3.1.11 是针对 3.1.10 实测日志的修复测试构建，**尚未发布到 GitHub**。

## 这次解决了什么

1. **设备端扫描仍报“没有 descriptor 目录”**
   - 日志里 `tree` 能列出 `61/Extensions/.../descriptors`，说明枚举器当时能看到目录；但前面的枚举和直接 `fileExists` 受沙箱打开时机影响，返回了空。
   - 3.1.11 不再另起一次枚举：**直接在打印 tree 的同一趟遍历里收集 `descriptors` 目录**，并返回布局。这样只要 tree 能看到，布局就一定能拿到。
   - 预期日志：`wallpaper: tree layout generation=61 extensions=[...全部 provider...]`，不再落到只含 CollectionsPoster 的 synthetic 布局。

2. **导入 `.tendies` 仍报 `unsafeArchive`**
   - 3.1.10 已修复解包后的 `isContained`：`/var/...` 与 `/private/var/...` 被当成两棵树，导致解包成功后仍被判定越界。
   - 3.1.11 增加导入阶段日志：`extracting` → `extracted` → `inspected`。如果仍失败，能直接看出卡在 ZIP 解包、包校验还是最终 rename。
   - 两个附带的实际包已审计：444/462 个条目，C 解包器 0 失败，包本身没有问题。

3. **版本混淆**
   - 启动第一行现在打印版本：`app: 3106 3.1.11 (15) launching ...`。如果日志里没有这行版本，说明安装的不是 3.1.11。

## 验证方法

1. 安装 3.1.11，确认日志第一行是 `3106 3.1.11 (15)`。
2. 进入壁纸页，日志应出现 `wallpaper: tree layout generation=61 extensions=[...]`。
3. 重新导入 `枯木逢春.tendies`、`四季双模式.tendies`，应依次看到：
   - `wallpaper: extracting ...`
   - `wallpaper: extracted ...`
   - `wallpaper: inspected ... descriptors=...`
   - `wallpaper: install ...`
4. 若仍失败，把 `wallpaper: extracting/extracted/inspected` 之后的第一条错误行发回。
