# 3106 3.1.9 测试版（未发布）

发布日期：2026-11-10

3.1.9 是针对 3.1.8 反馈的修复测试构建，**尚未发布到 GitHub**。

## 修复内容

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 壁纸扫描仍然看不到 descriptors | 3.1.8 只调用了 `resolvingSymlinksInPath()`，iOS 上它没有把 `/var` 变成 `/private/var`，扫描路径与授权路径仍不一致 | 扫描前显式调用容器路径 canonical 化，强制 `/private/var` 前缀 |
| 动态 `.tendies` 导入报 `unsafeArchive` | ZIP 解包层拒绝了常见的 Windows/中文包特征：GB18030 文件名、反斜杠路径、重复目录项、超过 256MB 的视频条目 | 增加 GB18030 文件名回退、反斜杠归一化、重复目录容忍、单条目上限提升到 768MB，并补充具体拒绝原因日志 |
| 清理页切到文件页卡 2-3 秒 | 每次 reload 都清空 LaunchServices 快照缓存，重复解析 18MB 数据库、重复做 6-13 秒文件系统扫描，并执行 491 个 MHA 候选激活 | 快照/标识符/文件系统列表复用 10 秒；显式刷新才清缓存；LS 已识别 ≥75% 容器时跳过 MHA 扫描 |

## 验证方法

1. 安装 3.1.9，重新导入 `枯木逢春.tendies`、`四季双模式.tendies`。
   - 成功：日志应出现 `wallpaper: scan root=/private/var/...`、`wallpaper: layout generation=61 ...`、`wallpaper: install ...`。
   - 失败：新日志会给出更具体的原因，例如 `zip entry too large`、`unsupported compression method=...`、`zip entry is encrypted`、`zip duplicate file entry ...`、`zip entry name decoded as GB18030`。
2. 清理页开始扫描后切到文件页，应明显变快；日志应出现 `browser: filesystem cache hit ...` 和 `browser: skipping MHA scan — filesystem resolved ...`。
3. 确认不再弹更新提示，设置页显示 `3.1.9`。
